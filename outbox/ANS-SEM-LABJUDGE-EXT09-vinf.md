## ① CIRC 重做立项（主线B见证证书化内嵌A，C仅探针，AC1–AC5）

**路线选择：稳健。**
- 把 C 限定为“探针”而非并列主线，实质是把不确定性隔离在可丢弃的观测层，主线 A/B 的契约不被探针污染。这是典型的“观测与授权分离”原则，方向正确。
- 将重做动机绑定到“见证证书化”（witness 证书化内嵌 A），使立项理由可追溯、可冻结，避免重做变成无限迭代的口袋。

**验收判据可否机器复核：可以，但需补一条形式化。**
- AC1–AC5 若都是“存在/不存在某见证、某证书字段、某探针调用路径”这类谓词，则天然可静态或运行时校验。
- 风险点：AC 中若混入“C 仅探针”的主观判断（例如“探针不得影响主线”），机器难判。建议明确 AC 中对应项为**调用图约束 + 副作用谓词**（如：C 的所有出边不得写入主线状态，且探针执行前后主线状态哈希不变）。补此一条即闭环。

**制度漏洞：无重大漏洞。**
- 唯一需要注意的是“主线 B 见证证书化内嵌 A”若允许 A 的更新反向改写 B 的见证格式，会产生隐式耦合。建议在 AC 中加一条“A 变更不得使已签发 B 见证失效，除非走显式版本迁移”。

**评定：pass。**

## ② 缓存锚域限条款（fallthrough DONE 四条件 + BLOCKED 四触发 + 缓存锚 ≠ 内容认证）

**路线选择：稳健偏保守，方向对。**
- 明确“缓存锚 ≠ 内容认证”是本案最关键的一条，切断了“缓存命中即视为内容可信”的常见误推。这条单独就值得 pass。
- DONE 四条件与 BLOCKED 四触发构成闭合边界，思路正确。

**验收判据可否机器复核：基本可以，但边界需收紧。**
- DONE 四条件是合取式，逐条可判，好。
- BLOCKED 四触发是析取式，需确认四条互斥性或至少优先级明确，否则会出现“同时满足 DONE 与 BLOCKED”的判定歧义。机器复核在歧义下会 flaky。**建议加一条元规则：BLOCKED 优先于 DONE**（或反之），显式写入。
- “缓存锚 ≠ 内容认证”本身是禁止性命题，机器可复核为：任何以缓存锚为唯一前提推导内容认证的路径必须不存在。可做，但需要在实现层给出可检测的“唯一前提”定义（例如证书链中锚只作索引不作签名）。

**制度漏洞：有一处需点名。**
- **fallthrough 与 BLOCKED 的衔接**：若 fallthrough 在前、BLOCKED 判定在后，存在“先 fallthrough 再发现应 BLOCKED”的窗口，此时状态已被污染。需要有事务性或回滚保证，否则 DONE/BLOCKED 的边界在并发下会被击穿。
- **反对票？不提。** 但附保留：若②最终文本未包含“BLOCKED 优先 + fallthrough 可回滚”两条，我会在下一次评审改投反对。当前按草案表述，判 pass with reservation。

**评定：pass（附保留）。**

## ③ A1 堆叠升级（L0 确权锁边界，L1/L2 契约 JSON 化，DISPUTED 停层）

**路线选择：稳健。**
- L0 只做确权锁边界，不越权承载业务语义，层级分离干净。
- L1/L2 契约 JSON 化使跨层校验可自动化，是正确方向。
- DISPUTED 停层是安全默认（fail-closed），符合“争议时不动”的原则。

**验收判据可否机器复核：可以，且是三案中最彻底的。**
- JSON 化契约天生可 schema 校验，L1/L2 的输入输出可机器比对。
- L0 边界若定义为“键空间 + 权限谓词”，也可静态校验。
- DISPUTED 停层可复核为：处于 DISPUTED 的层不得产生对外的状态转移边。

**制度漏洞：停让规则有一处需补。**
- **停层是否传播？**若 L1 进入 DISPUTED，L2 是否自动停？若否，则 L2 可能基于未确权的 L1 输出继续推进，形成“下层停、上层跑”的漏洞。建议明确：**停层沿依赖方向向上传播，直到某个显式豁免层**。
- 另外，DISPUTED 的解除条件需写明，否则停层可能永久化，变成事实上的死锁。

**评定：pass。**
